# ADR 0009 — Value adapter contracts, engine identity, cấu trúc API và audit revision

Ngày: 2026-10-14. Trạng thái: chấp nhận cho kế hoạch Foundation Hardening, API Structure & Pluggable Adapters (cùng cách ADR 0001/0002/0004/0008 đánh dấu quyết định đã chọn trong kế hoạch); bằng chứng triển khai nằm ở checkbox/ledger của kế hoạch, chưa có code nào được ADR này chứng nhận.

## Quyết định

- **Ports giá trị.** Core khai báo `ValueCodecs` trong `packages/core/src/ports/value-codecs.ts` với sáu kind cố định: `timestamp`, `integer`, `decimal`, `uuid`, `string`, `boolean`. Mỗi kind là `ScalarCodec` (`normalize(input) -> T | undefined`, `compare(l, r) -> -1|0|1`). `normalize` không dùng clock, timezone máy, trim hay parse lỏng; `compare` chỉ nhận giá trị đã normalize. Không có `registerKind`, SQL callback hay `setDefaultAdapter`. Bảng codec được copy/freeze khi tạo runtime. Adapter là trusted code đăng ký lúc boot, không chọn từ payload. Adapter throw/trả sai không bao giờ thành allow (fail closed). Boolean/UUID vẫn chỉ equality.
- **Domain timestamp strict.** Chỉ UTC `YYYY-MM-DDTHH:mm:ss[.f{1..6}]Z`, năm `0001..9999`, output luôn sáu chữ số lẻ; microsecond giữ dưới dạng chuỗi, không qua `Date`/millisecond number. Từ chối: ngày không tồn tại (vd 30/2), tháng/ngày 0, giờ 24, giây 60, hơn sáu chữ số lẻ, offset, thiếu `Z`, whitespace, trailing junk; không truncate/round/đổi timezone. **Thay đổi hành vi có chủ ý:** các giá trị trước đây parser regex + `Date.parse` nhận (ngày không tồn tại, `24:00:00`, offset, độ chính xác bị mất) nay bị từ chối; không rewrite dữ liệu/audit lịch sử, giá trị cũ không hợp lệ phải được sửa ở nguồn. Day.js (strict `CustomParseFormat` + UTC, trong `packages/value-adapters`) là adapter đầu tiên; năm `0001/0099/0100` phải round-trip, không thu hẹp domain.
- **Engine identity và provenance.** `createAuthorizationCore({ values })` trả instance; `isValidated`/provenance của declarations, `prepareRelease`/`prepareProductRelease`, binding registries và services normalization gắn với đúng instance (WeakSet/metadata nội bộ, không vào canonical JSON hay manifest hash). Declarations validate bởi instance A bị từ chối ở instance B. Không có default engine toàn cục; composition root (`apps/api`, `tools`) chọn adapter.
- **Breaking change nội bộ có chủ ý.** Các hàm scalar/plan/evaluate của core chuyển thành method của instance; các package là private `0.0.0`, nên không giữ shim tương thích. Toàn bộ caller workspace (production, tools, legacy, tests) chuyển trong cùng nhóm task; task không hoàn thành khi còn đường production dùng parser cũ. Consumer ngoài workspace (nếu phát hiện) cần mapping riêng trước khi bỏ export. Bản đồ chuyển đổi API cũ sang mới nằm ở mục `Public API migration map` trong `docs/single-product-reuse-map.md`.
- **API theo capability.** `apps/api` tách `config`, `infrastructure`, `auth`, `documents`, `administration`, `health`, `authorization`, `openapi`; chỉ `RuntimeModule` giữ runtime/pools, module khác nhận facade token. Path/status/cookie/CSRF/OpenAPI HTTP không đổi. `audit-outbox.service.ts` chuyển sang `legacy/`, không xóa, không wire vào product runtime. Migration theo từng capability, không để re-export ở đường dẫn cũ.
- **Entrypoints `typeorm-postgres`.** `.` (service contracts an toàn), `./composition`, `./operations`, `./legacy`. Root không re-export lại nội dung đặc quyền; ESLint chặn feature handlers import typeorm/driver/composition/operations/legacy/private source. Đây là ranh giới cho developer, không phải sandbox.
- **Audit revision.** `policy_revision` giữ nghĩa là revision dùng để **đánh giá** quyền. Event mutation thêm `resultingRevision` (string, metadata allowlist) là revision sau commit (revoke/admin/bootstrap: `tx.revision + 1`; sync: revision reconciler công bố; read: không có). Writer cũ có nghĩa khác không bị rewrite. `account.suspend` ghi target user ID; `data.update` ghi resource + typed key/object ID. Helper nhận input có kiểu, không nhận metadata tùy ý từ HTTP; token/password/email/title/reason tùy ý không vào metadata. Effect và audit nguyên tử.

## Không đổi

DB clock (`statement_timestamp()` vẫn là clock quyết định quyền; codec không có `now()`), Root (không bypass, marker/bootstrap như ADR 0007/0008), application fence (exclusive/shared, revision cùng transaction), policy AND boundary ngoài mọi allow, default deny, single-product một database. Không thêm plugin manager, service locator, container DI trong core, cache allow hay phân vùng fence.

## Còn mở

Adapter thời gian thứ hai (vd Moment) chỉ thêm khi có consumer và phải vượt cùng conformance suite. Generic administration, delivery/retention audit và vận hành provider thật nằm ngoài ADR này; không gọi production-ready.

## Implementation note — audit (T5)

- Mốc semantics: từ thay đổi này mọi product writer ghi `audit_outbox` qua `appendProductAudit` (`packages/typeorm-postgres/src/product-audit.ts`), không thêm migration. `policy_revision` = `tx.revision` (revision đã đánh giá dưới fence). Event mutation có `safe_metadata.resultingRevision`: `write`/`identity` = `tx.revision` (không đổi), `revoke`/`admin`/`bootstrap` = `tx.revision + 1`, `manifest.sync` = revision reconciler publish. Event `access.*` (obligation `audit@1`) không có `resultingRevision`.
- Event cũ không bị rewrite. Trước mốc này `account.suspend`, `data.update`, `access.*` trong mode admin, `manifest.sync`, `root.*` và `identity.enroll` ghi `policy_revision` là revision sau commit và không có `resultingRevision`; event có `resultingRevision` là event theo semantics mới.
- Target: `account.suspend` ghi `targetUserId` (actor là người thực hiện); `data.update` ghi `object_id` (cột có sẵn, lấy từ `objectIdColumn` của binding) cùng `resource`, `keyKind`, và `key` chỉ khi key kind là `uuid`/`integer` (key `string` có thể là PII nên không vào metadata). Lệnh offline (`manifest.sync`, `root.bootstrap`/`root.reissue`/`root.revoke`, `identity.enroll`/`identity.invite`) ghi `actor_id` là sentinel `PRODUCT_OFFLINE_ACTOR` (một hằng số duy nhất), target account ở `targetUserId`; danh tính operator/approver nằm trong bản ghi approval được tham chiếu. Trước mốc này `root.*`, `identity.enroll`/`identity.invite` ghi target làm `actor_id`. Metadata chỉ gồm field typed của từng kind; title/token/password/email không vào metadata; `reason` chỉ của `root.revoke` (input offline đã validate) ở cột riêng.
- Obligations: `ProductAuthorization` nhận registry typed `Readonly<Record<string, ProductObligationHandler>>` lúc composition (frozen copy); danh sách handler cho core suy ra từ đúng key của registry. Thiếu handler thì planner deny; handler throw thì transaction rollback, không payload/effect/event. `productObligations` đăng ký `audit@1` thật; API runtime và CLI sync dùng cùng registry.
